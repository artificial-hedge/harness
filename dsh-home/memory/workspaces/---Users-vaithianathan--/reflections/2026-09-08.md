# 反思 2026-09-08

成果回顾：完成Mac高CPU进程诊断，确认设备有10个逻辑核心，主要负载来自WindowServer、Superset、Docker/Colima、ANECompilerService和Multica。随后停止并清理Superset、Docker Desktop和Multica的应用及用户级支持数据，保留了Multica工作区项目；复查确认相关应用进程、应用数据和Docker系统服务文件均已不存在。另完成显示卡顿诊断，确认问题更接近WindowServer与系统交换压力，而非DSH后端。

值得注意的教训或改进：macOS的CPU百分比按单个逻辑核心计算，超过100%表示多核占用；卸载桌面应用时需同时检查转置应用路径、用户级支持目录、容器数据和root-owned系统服务。涉及Docker时应区分Docker Desktop数据与Colima工作区，避免误删仍需保留的项目。

今日可延续的要点：若系统仍卡顿，优先复查WindowServer、交换区和当前图形/虚拟机负载；若重新卸载带有特权组件的应用，先停止进程，再核对应用包、用户数据、LaunchDaemon和PrivilegedHelperTools，最后做一次进程与路径复查。
